8. CMDS Zotero 0.3.0의 위치 요약

우리만 있는 것: 정규 아이덴티티 인덱스와 진단, 섹션별 해시 보존(편집 감지), citekey 히스토리로 이름·키 변경 추적, 다른 볼트 note-map 탐색, Hookmark 호환 링크, ingest CLI, 설치 이전·롤백 스크립트, Zotero·볼트 모두에 대한 보수적 쓰기 경계.

ZotLit에만 있는 것: 본문 인용 렌더링·팝오버, DOCX/HTML 내보내기, Zotero 리더 따라가기, 라이브러리·컬렉션 배치, 컴패니언 우클릭 진입, 템플릿 엔진과 Workbench, Zotero 종료 상태에서도 동작, 자식 노트 별도 파일 가져오기.

Zotero Integration만의 유산: Nunjucks persist 템플릿과 PDF Utility 이미지 추출. 유지보수 중단으로 대체 대상.

0.3.0에서 의도적으로 제외한 것: 템플릿 엔진, SQLite 직접 읽기, 컴패니언 애드온, HTTP 리스너·live update, 양방향 동기화, DOCX 내보내기, MCP 노출. 근거는 레포 docs/plugin-landscape-2026-09.md.

남은 실측: 0.3.0 서제스터·두 사이드바·일괄 갱신·v2 레이아웃 가져오기·0.2.0 노트 재가져오기(Zotero 실행 상태 필요). 그룹 라이브러리와 Hookmark 왕복은 0.2.0부터 미검증.

9. 판단: 직접 개발 vs 기존 플러그인 (2026-09-14 추가)

결론: 역할 분담. 글쓰기·읽기 UX는 ZotLit, 에이전트·위키 인프라는 CMDS Zotero. Zotero Integration과 Pandoc Reference List는 아카이브 상태이므로 비활성화.

영역 선택 이유
인용 삽입·본문 렌더링·팝오버·DOCX 내보내기·리더 따라가기·컬렉션 배치 ZotLit 우리가 만들지 않기로 한 기능. 활발한 유지보수(2026-07~09 릴리스 20회), Zotero 10 대응
[@ 서제스터·References·Annotations 사이드바 ZotLit 우선, CMDS는 폴백 0.3.0에서 만든 부분 중 가장 겹치는 영역. 동시에 켜면 서제스터가 둘 다 뜨므로 CMDS 쪽 완성은 Off
정규 아이덴티티 인덱스 JSON, ingest.mjs CLI, resolved/ambiguous/unavailable 구분 CMDS Zotero paper-ingest 스킬과 Claude Code 에이전트가 읽는 계약. ZotLit은 사람용 UI
문헌노트 보존 모델 CMDS Zotero ZotLit은 관리영역 통째 교체(영역 안 편집 소실). CMDS는 섹션별 해시로 편집 감지·보존·보고. 에이전트가 노트를 만지는 위키에 필요
두 볼트 note-map, 이름·citekey 변경 추적, Hookmark 링크 CMDS Zotero ZotLit에 없음
Zotero 연결 안정성 CMDS 유리 ZotLit v1은 네이티브 SQLite 바인딩이 Electron 업데이트마다 파손, v2는 DB 파일 직접 읽기+컴패니언. CMDS는 BBT RPC만 사용
라이선스 — ZotLit은 AGPL. 코드 차용 불가
