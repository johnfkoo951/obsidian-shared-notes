제작 요청 요약

CMDS 옵시디언 클래스의 통합 랜딩 1개를 제작합니다. 네 과정을 독립적으로 소개하고, 온라인/오프라인 선택과 전체 패키지 선택을 지원합니다. 같은 커리큘럼을 여러 사이클로 열어, 과정마다 다른 사이클에서 이수할 수 있게 합니다. 지금 진행할 일은 랜딩 제작입니다. 실제 공개, 개인정보 수집 폼 개통, 결제 개통은 구요한 확인 후 진행합니다.

  • 게시용 콘텐츠 정본: 2026-09-14-01-클래스-커리큘럼-최종. 파일의 YAML frontmatter를 제외한 본문을 사용합니다.
  • 이 지시서와 2026-09-14-03-근거검토-교육운영-인계목록은 제작자용입니다. 홈페이지 본문이나 다운로드 디렉터리에 올리지 않습니다.
  • 파일 이름의 최종은 커리큘럼 편집본을 뜻합니다. 금액/일정/정원/약관까지 승인되었다는 뜻이 아닙니다.
  • 클래스 코드 B/C/W/A는 과정 구분입니다. AKM 기준 P1/C1 등과 다른 체계입니다. 모듈은 B01/C01/W01/A01처럼 두 자리로 표기합니다.

  • 혼합 패키지 예: 기초만 오프라인, 나머지는 온라인 = 129,000 + 249,000 + 99,000 + 299,000 - 77,000 = 699,000원.
  • 참여 방식별 추가 금액: 기초 +50,000원, CMDS +100,000원, Wiki +50,000원, 에이전트 +100,000원. 전체 온라인 649,000원에 선택한 현장 과정 차액을 더하면 됩니다.
  • 할인 규칙은 동시에 네 과정을 구매하는 패키지의 제안입니다. 기존 단과 구매자의 사후 패키지 전환, 쿠폰 중복, 취소 시 환불 배분은 별도 확정합니다.
  • 날짜/이용기한/취소 규정 미확정 상태에서는 결제를 열지 않습니다. 관심 등록 폼도 수집 목적과 보관 기간 등 고지를 확인한 후 개통합니다.

온라인 무정원과 기술 수용량은 별개

  • 판매상 온라인 정원은 두지 않습니다. 실제 접속 인원에 맞는 회의/웨비나 라이선스, 호스트 권한, 질문 관리 수단을 확보합니다.
  • 현재 계정이 몇 명을 받을 수 있는지 미검증입니다. 플랫폼 한도를 이유로 온라인 학생이 당일 입장하지 못하는 상황을 방지해야 합니다.
  • 라이브 전체에서 전원 화면 공유를 전제로 하지 않습니다. 실습은 개인 진행, 제출은 공통 양식, 피드백은 공통과 대표 사례 중심으로 설계합니다.
  • 태극님이 진행 운영까지 맡는 것은 이번 랜딩 제작 요청과 별개의 업무입니다. 라이브 기술 호스트와 질문 정리 담당의 배정을 별도로 확정합니다.
  • 송출에서는 강사 화면/음성/공통 예제만 기본 노출합니다. 수강생 화면, 이름, 개인자료, 얼굴의 송출/녹화는 별도 동의 없이 포함하지 않습니다.

사이클과 수강권

데이터 모델

  • 과정: B/C/W/A.
  • 사이클: 같은 네 과정을 반복 개설하는 묶음. 수강생의 고정 기수와 같지 않음.
  • 차시: 과정 안의 개별 수업.
  • 참여 방식: 과정별 온라인/오프라인.
  • 수강권: 구매 과정과 이용기한.
  • 예약: 수강권에 연결된 과정별 사이클과 참여 방식.
  • 출석/이수/재수강: 서로 다른 상태.

선택 화면

  1. 단과 또는 전체 패키지를 선택합니다.
  2. 과정별 참여 방식과 개설 사이클을 선택합니다. 단과는 해당 과정만 표시합니다.
  3. 선수역량, 일정 중복, 오프라인 잔여석, 이용기간을 확인합니다.
  4. 선택한 총액과 환불/예약 변경 조건을 확인한 뒤 결제합니다. 이 단계는 조건 승인 후 활성화합니다.

반드시 가능한 경로

  • 기초는 사이클 1, CMDS/Wiki/에이전트는 사이클 2.
  • 기초/CMDS는 사이클 1, Wiki는 사이클 2, 에이전트는 사이클 3. 사이클 3 개설 시에만 실제 예약 가능.
  • 온라인/오프라인을 과정별로 섞는 방식은 위 가격 규칙으로 구현할 수 있게 준비합니다. 이 혼합 방식 자체의 최종 운영 승인도 받습니다.

좌석과 예약 원칙

  • 오프라인 정원은 과정×사이클 단위로 관리합니다. 같은 과정의 모든 차시를 묶어 예약하는 것이 기본입니다.
  • 현장 잔여석 = 정원 - 유효 예약. 유효 예약에는 이전 사이클에서 넘어온 학생도 포함합니다.
  • 온라인에는 잔여석 개념을 사용하지 않습니다. 모집 마감일이 있다면 정원 마감과 구분합니다.
  • 패키지는 네 과정을 완주할 수 있는 예약 조합을 확인한 뒤 판매합니다. 미래 개설을 무기한 약속하지 않습니다.
  • 수강하지 않은 과정을 뒤 사이클에서 듣는 것은 최초 이수이고, 이미 이수한 과정을 다시 듣는 것은 재수강입니다. 무료 무제한 재수강을 붙이지 않습니다.
  • 차시별 분할 이동, 예약 변경 마감, 결석/노쇼, 이용기간 만료, 폐강 시 대체/환불, 온/오프라인 변경 차액 정책은 운영 승인 후 명시합니다.

랜딩 섹션 구성

  1. 히어로: 프로그램명, 기록→지식→실행의 한 줄 가치, 온/오프라인 안내.
  2. 수강 대상: 기록 시작/내 볼트 설계/학습 위키/반복 업무 네 가지 선택.
  3. 메인 볼트와 Wiki 역할 설명: 01의 세 가지 설계와 핵심 문장을 사용.
  4. 네 과정 비교: 시간, 선수역량, 산출물, 온라인/오프라인 가격 선택.
  5. 상세 커리큘럼: 01의 모듈을 과정별 아코디언으로 노출. 내용 임의 삭제 금지.
  6. AKM 연결: 다섯 질문과 실제 증거 중심 점검. 점수 보장, 공식 자격증, 인증기관 문구 금지.
  7. 수강 경로와 사이클 교차 수강 예시.
  8. 참여 방식 비교와 준비 사항.
  9. 강사 소개와 공식 프로필 링크.
  10. FAQ, 일정/가격/약관 확인 후 신청 CTA. 추가 행사 CTA는 기존 labs 공통 푸터 규정이 적용되는 경우 검증된 행사 데이터로만 구성합니다. 다른 상품을 본 과정과 같은 패키지로 묶거나 미확정 행사를 발명하지 않습니다.

게시 문구와 숨겨야 할 문구

  • 01 본문: 게시용. YAML은 제거.
  • 02 전체: 제작 지시이므로 비공개. 승인된 가격과 참여 조건만 별도 UI로 옮김.
  • 03 전체: 근거/QA/내부 운영이므로 비공개.
  • 학생 수, 후기, 점수 상승, 시간 절감률, 사전 선발 인원 등 실측 없는 숫자 금지.
  • 오늘 세미나의 신청자 명단, 신청 수, 원본 CSV를 새 유료 과정의 실적으로 쓰지 않음.
  • 작동 화면은 실제 예제 화면으로 캡처. 학생 개인정보, 내부 경로, 파일명, API 키를 가린 뒤 사용. 생성형 이미지로 실제 제품 화면을 만들어내지 않음.
  • 개인정보 포함된 개인 볼트나 내부 시스템 파일을 다운로드 자료로 게시하지 않음.

FAQ 문구

처음부터 모두 들어야 하나요?

필요한 과정만 선택할 수 있습니다. 심화 과정에는 필요한 사전 경험이 있으며, 앞 과정 수료 또는 동등 경험으로 확인합니다.

온라인과 오프라인에서 배우는 내용이 다른가요?

핵심 커리큘럼과 학습 목표는 같습니다. 오프라인은 현장 참여와 실습 시간 내 순회 피드백이 포함되며, 좌석 제한에 따라 모집합니다.

한 사이클에 모두 들어야 하나요?

아닙니다. 개설 일정과 이용기간에 맞춰 과정별로 다른 사이클을 선택할 수 있습니다. 오프라인은 해당 과정의 좌석 예약이 필요합니다.

AI 구독료가 포함되나요?

AI 구독 또는 API 사용료는 수강료와 별도입니다. 필요한 환경과 계정 준비는 각 과정 안내에서 확인합니다.

AKM 점수를 보장하나요?

아닙니다. 실제 시스템의 증거로 현재 상태와 개선 방향을 살펴봅니다. 수료 여부를 특정 점수나 성숙도 등급으로 바꾸지 않습니다. 녹화 제공, 지원 OS, 설치지원, 기간, 환불 FAQ는 미확정이므로 임의 답변을 쓰지 않습니다.

  • 온라인 동시접속 수용량과 기술 운영 담당 확보.
  • 오프라인 정원과 과정별 예약 정책 확정.
  • 온/오프라인 금액, 할인 적용 조건, 결제총액/증빙 확인.
  • 이용기한, 재수강, 방식 전환, 변경/취소/폐강/환불 정책 확정.
  • 교재/녹화/질문 지원 범위와 열람 기산일 확정.
  • 개인정보 수집과 송출/녹화 동의 분리, 제출/공개 선택 분리.
  • 비공개 검토, 결제 테스트, 구요한 공개 승인.
